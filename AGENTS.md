## Decision Matrix

```typescript
function shouldUseCodeMode(task): boolean {
  if (task.mcpCallCount >= 3) return true;      // Multiple tools
  if (task.requiresParallel) return true;       // Parallel needed
  if (task.isReusable) return true;             // Will reuse
  if (task.hasDataProcessing) return true;      // Filtering/mapping
  if (task.isEnsemble) return true;             // Multi-model
```

## Test-Driven Development (TDD)
TDD is required for:
- New functions/classes/modules
- Any logic/behavior change
- Bug fixes (regression test required)

If behavior is unchanged: run existing tests; add missing coverage only if gaps block confidence.

**Trivial Skip Criteria** (ALL must be true):
- Change is ≤5 lines of code
- No new functions, classes, or methods
- Change is docs/config/typo only

### Stateful TDD Workflow

TDD is a **gated state machine**. Do not proceed without completing each state.
States:
- RED: write the failing test (prove the spec exists).
- GREEN: implement minimally until the test passes.
- REFACTOR: clean up while keeping the suite green.

### Evidence Requirements

Evidence is required for RED and GREEN (and ideally for full-suite after refactor):
- RED: pasted output showing the test fails.
- GREEN: pasted output showing the test passes.
- REFACTOR: pasted output showing the relevant suite still passes.

### Anti-Cheat Rules

These patterns indicate TDD evasion:
- `skip` / `xfail` to avoid enforcement
- Trivial assertions (`assert True`, `is not None`) instead of behavioral checks
- Weakening assertions to “make it green”
- Over-mocking so the behavior isn’t exercised

**Rule**: If you use skip/xfail, document explicit user approval in the commit message.

### Traceability

For medium/large changes, include a short mapping of:
- PRD task → test id(s) → test file → what the assertions prove

**Naming convention**: `test_prd_{task_id}_{description}`

Before committing:
- TDD followed when required (RED → GREEN → REFACTOR)
- Evidence captured for RED + GREEN
- Relevant tests pass

## Environment Edge Cases

### Tests Cannot Run

If test harness is broken/missing:
1. **STOP** and inform user
2. If user approves continuing:
   - Still **write** the test code
   - Document expected failure reason
   - Write implementation
   - Mark with: `[Tests written, not executed - env issue]`
3. Run tests when environment is fixed

### Test Command Unknown

Check in order:
1. `pytest` / `python -m pytest`
2. `cargo test`
3. `npm test` / `deno test`
4. `make test`
5. Check `pyproject.toml`, `package.json`, `Makefile`

If still unknown: **STOP** and ask user.

When writing prompts that require TDD compliance, include these elements:
Use:

## Quick Reference

### TDD States
```
RED    → Test fails (proves spec exists)
GREEN  → Test passes (proves implementation works)
REFACTOR → Code cleaned (proves no regressions)
```

### Evidence Template
```markdown
--- STATE 1: RED ---
> pytest tests/test_X.py -v
FAILED ... <paste actual output>

--- STATE 2: GREEN ---
> pytest tests/test_X.py -v
PASSED ... <paste actual output>

--- STATE 3: REFACTOR ---

```

- Writing implementation before tests
- Tests that pass trivially
- Claiming tests ran without evidence
- Using skip/xfail to avoid failures

| I1 | **rag-core has ZERO I/O dependencies** — No tokio, reqwest, or network code. All I/O abstracts through traits (`EmbeddingBackend`, `Rerank`). | Enables library reuse, testing with mocks, and future Python bindings. |
| I2 | **Reranker failure MUST NOT halt searches** — If `RerankerService` is unavailable or fails, search continues using embedding scores only. | Graceful degradation ensures availability. |
| I3 | **Only ONE reindex job can run at a time** — Enforced via atomic SQLite transaction with `WHERE NOT EXISTS`. | Prevents resource exhaustion and index corruption. |
| I4 | **Write locks are per-document, not per-job** — Lock held for seconds (chunk finalization), not hours (full reindex). | Searches remain responsive during indexing. |
| I5 | **Embedding dimension change triggers reindex** — If `embedding_dim` on disk differs from model, `needs_reindex = true`. | Prevents cosine similarity errors from mismatched vectors. |
| I6 | **All timestamps stored in UTC** — Job timestamps use Unix epoch seconds. | Consistency across time zones. |
| I7 | **NaN/Inf scores are filtered, not propagated** — Invalid scores skip MMR aggregation. | Prevents score explosion and ranking corruption. |
| I8 | **Chunk text is never split mid-sentence** — Sentence-aware chunking preserves semantic coherence. | Better embedding quality for retrieval. |
| I9 | **Document hashes detect changes** — SHA-256 computed at ingestion; unchanged documents skip re-embedding. | Efficient incremental indexing. |
| I10 | **CPU-bound work uses spawn_blocking** — PDF extraction, text chunking run in blocking thread pool. | Prevents async runtime starvation. |

## 5. Critical Workflows (The Logic)

### Workflow: Document Indexing (`start_reindex`)

**Trigger:** MCP client calls `start_reindex` tool.

**Behavior:**

```
1. JobManager.create_reindex_job_if_not_active():
   - BEGIN TRANSACTION
   - SELECT COUNT(*) FROM jobs WHERE status IN ('pending', 'inprogress')
   - IF count > 0: RETURN existing job (no new job created)
   - INSERT INTO jobs (job_id, status='pending', ...) RETURNING *
   - COMMIT
   → Guarantees: Atomic, only one active job possible

2. Send JobRequest::StartReindex via mpsc channel to WorkerSupervisor

3. WorkerSupervisor spawns async task:
   a. Update job status = InProgress
   b. Scan DOCUMENTS_DIR for *.pdf files
   c. Set job.total = file count

4. For each PDF file:
   a. Compute SHA-256 hash of file bytes
   b. IF hash matches stored hash: SKIP (document unchanged)
   c. Extract text:
      - TRY: lopdf (pure Rust) in spawn_blocking
      - CATCH: fallback to pdftotext command
      - BOTH FAIL: Log error, mark as poison pill, CONTINUE
   d. Chunk text (sentence-aware, ~200 tokens target):
      - Split into sentences via regex
      - Build chunks from complete sentences only
      - Track metadata (page ranges, section titles)
   e. Batch embed chunks:
      - Acquire write lock briefly (TimedWriteLockGuard)
      - Call embedder.embed_batch([chunk_texts])
      - Release lock
   f. Upsert chunks to index + SQLite
   g. Update job.progress++
   h. Persist document hash

5. On completion:
   - IF any poison pills: job.status = Failed, job.error = summary
   - ELSE: job.status = Completed
```

### Workflow: Semantic Search (`search_documents`)

**Trigger:** MCP client calls `search_documents` with query.

**Behavior:**

```
1. Validate SearchRequest:
   - top_k: clamp to [1, 100]
   - diversity_factor: clamp to [0.0, 1.0]
   - weights: filter NaN/Inf values, use defaults for invalid

2. Build QuerySpec from request

3. Acquire read lock on RagEngine

4. Stage 1 - Initial Retrieval:
   a. Get query embedding:
      - CHECK LRU cache (1000 entries)
      - IF miss: Call embedder.embed(query), store in cache
   b. AnnIndex search: cosine similarity over all chunks
   c. LexicalIndex search: BM25-style keyword matching
   d. Combine scores:
      initial_score = (embedding_weight × emb_score) + (lexical_weight × lex_score)
   e. Apply filters (FilterExpr evaluation)
   f. Apply boosts (BoostSpec multiplication)
   g. Select top 3×top_k candidates

5. Stage 2 - Reranking (if RerankerService available):
   a. Build RerankerCandidate for each candidate
   b. Concurrent LLM scoring via futures::join_all:
      - Send prompt: "Does this chunk answer the query? Yes/No"
      - Parse logprobs: score = softmax(yes_logprob, no_logprob)
      - FALLBACK: text-based Yes/No detection
      - FALLBACK: use initial_score if reranking fails
   c. Blend scores:
      final_score = (initial_weight × initial_score) + (reranker_weight × reranker_score)

6. Stage 3 - Diversification (if diversity_factor > 0):
   a. Apply MMR algorithm:
      mmr_score = (1 - λ) × relevance - λ × max_similarity_to_selected
   b. Select top_k diverse results

7. Build SearchResult array with full score breakdown

8. Release read lock, return results
```

### Workflow: Job Status Polling (`get_job_status`)

**Trigger:** MCP client calls `get_job_status` with job_id.

**Behavior:**

```
1. Query SQLite: SELECT * FROM jobs WHERE job_id = ?
2. IF not found: Return MCP error (resource_not_found)
3. Format response with:
   - status (Pending/InProgress/Completed/Failed)
   - progress / total (e.g., "42/100 documents")
   - error (if Failed)
   - started_at, updated_at
```

`rust-local-rag` is a Rust MCP server that provides **local RAG** (Retrieval-Augmented Generation) over a directory of PDFs:

## Engineering Guardrails (important invariants)

**Warnings are errors**:
- `.cargo/config.toml` sets `-D warnings`. Keep builds/clippy warning-free.

**Async + blocking work**:
- Do not block Tokio runtime. Use `tokio::task::spawn_blocking` for CPU-bound / blocking work (PDF extraction, embedding calls, heavy parsing).

**Locks**:
- The shared engine is `Arc<RwLock<RagEngine>>`. Keep write locks short.
- Indexing uses per-document locking; don't reintroduce "hold write lock for entire reindex" behavior.

**Jobs**:
- Reindexing runs as background jobs (SQLite persistence + supervisor).
- Preserve "single active reindex job" semantics (atomic check-and-create).
- Poison-pill behavior: a single document failure should not abort the whole job.

**Persistence**:
- Indexes are model-partitioned (`chunks_{sanitized_model}.json`), plus SHA-256 document hashes.
- If you change persistence format/semantics, add a migration path and update docs.
